# 阶段三 · PRD —— QQ 记账机器人「一句话记账，主动帮你坚持」

> 课程：AI 产品开发 · 阶段三（Week 7 PRD）
> 定位：个人记账坚持路线。v1 只做 QQ 官方 Bot；微信/钉钉/飞书为扩展方向；App/Web/第三方客户端多端账单同步。
> 配套：`docs/阶段三-立项-QQ记账机器人.md`（一句话立项 + 答辩弹药）；Week 8 按本 PRD 编码。

---

## 1. 背景与问题

- 记账 App 30 日留存极低。根因不是"不想记"，而是**单次动作摩擦太高 + 没有主动提醒**：≥6 步记一笔，忘了记还要补记，坚持不下来。
- 目标人群：**学生、上班族**——"下了 App 却常常忘记记账"，反复下载又卸载。
- 机会：他们**每天都泡在主流社交媒体（QQ/微信/钉钉/飞书）**上。把记账"搬进聊天"，就是搬进用户已经在的地方——不用再打开任何记账 App。

## 2. 目标与非目标

**目标（目前是QQ）**

1. 用户**不打开任何记账产品**，在 QQ 里说一句「午餐28元」就完成记账。
2. 机器人**主动推送**（月度总结 / 异常提醒 / 习惯提醒），形成"被动记账"习惯回路。
3. 数据上云，**App / Web / 第三方客户端多端账单同步**。
4. 用户**处理账单时**，再使用**App详细规划**

## 3. 目标用户与使用场景

| 用户 | 典型场景 | 一句话价值 |
|---|---|---|
| 大学生 | 三餐/娱乐/网购，月底"钱去哪了" | 随口记，月底有人告诉我 |
| 年轻上班族 | 通勤/外卖/应酬，忙起来忘了记 | 不打开 App，聊天里顺手记 |

**生命周期示例**
1. 用户通过App加上机器人好友，发任意消息 → 机器人引导开通（QQ 即账号，无需 App）。
2. 发「午餐28元」→ 回复「已记录：三餐 ¥28.00」。
3. 月末 31 日 20:00 → 收到本月消费总结卡片。
4. 某日支出异常 / 预算将超 → 收到异常提醒。
5. 常用时段（午餐点）未记账 → 收到快记提醒。
6. 用户也可打开 App / Web 看完整账单与图表，数据实时同步。

## 4. 使用流程（一句话）

> 在 QQ 里说一句「午餐28元」就记好账，月底自动收到消费总结和异常提醒，靠主动推送帮你把记账坚持下来。

```
用户发消息 ─→ 机器人 NLU 分流
              ├─ 记账句（含金额）→ 落账 → 回复「已记录：三餐 ¥28.00」
              ├─ 问账句（多少/几笔）→ 查库 → 回复统计
              └─ 纠错句（删除/记错了）→ 删除 → 回复确认
定时任务 ─→ 主动推送
              ├─ 月度总结卡片（月末）
              ├─ 异常提醒（当日超日均 ×1.5）
              └─ 习惯提醒（按时段行为数据）
```

## 5. 功能需求

### FR1 被动接收：一句话记账（P0）
- 输入：「午餐28元」「打车花了20」「工资8000」「给妈妈买礼物58元」。
- 输出：`已记录：三餐 ¥28.00`（分类 + 金额）。
- 规则：含明确金额即记账；规则引擎本地先判，LLM 兜底复杂表达；断网/服务降级也能记账。
- **验收**：≤300ms 回复（无 LLM 时）；金额/分类正确率 ≥95%（规则通道）。

### FR2 被动接收：问账（P0）
- 输入：「今天花了多少」「这个月花了多少」「打车花了多少」「最近几笔」「这个月预算」。
- 输出：对应统计文本；分类/月/日粒度。
- 验收：数据与服务端一致（同一 `BillService` 数据源）。

### FR3 被动接收：纠错（P1）
- 输入：「删除午餐」「删掉刚才那笔」「记错了」。
- 输出：删除最近 10 笔内匹配项并确认；不匹配则提示候选。
- 验收：删除为软删除，可在 App/Web 侧同步看到。

### FR4 主动推送：月度总结卡片（P0）
- 触发：每月最后一天 20:00（上海时区），用户当月有 ≥1 笔记录。
- 内容：总支出 / 总收入 / 支出 TOP 分类 + LLM 生成的一句话总结 + 亮点（聚合数据，无明细）。
- 验收：推送成功率 ≥95%；未绑定/无数据不推送。

### FR5 主动推送：异常提醒（P1）
- 触发：当日支出 > 近 30 日均值 ×1.5；预算使用将超。
- 内容：`今天支出 ¥180，超出日均 ¥90 的 100%`。
- 验收：纯本地计算，不调 LLM，零外传。

### FR6 主动推送：习惯/快记提醒（P2）
- 触发：用户近 7 天在"午餐时段"有 ≥3 次同分类同金额记录，且今日该时段未记。
- 内容：`午餐时段你常点 三餐 ¥28，记得记一笔吗？`
- 验收：尊重关闭开关；不打扰（每天最多 1 条）。

### FR7 多端账单同步（P0）
- 服务端为唯一数据源，`GET /api/bills/sync`（复合游标分页）+ 软删除墓碑，App / Web / 机器人写入走同一写接口。
- 机器人落账 → App/Web 秒级可见（依赖现有同步协议，5 分钟周期 / 手动刷新）。
- **验收**：机器人记一笔，App 与 Web 账单列表出现该笔；任一端删除，其它端同步。

### FR8 账号体系：QQ 即账号（P0，独立产品关键）
- 首次发消息即开通（QQ openid 绑定新账号），**无 App 前置**。
- 后续在 App/Web 登录同一账号即同库同账单。
- **验收**：从加好友到记下第一笔 ≤3 条消息，全程不碰 App。

### FR9 平台扩展预留（P2）
- NLU / 洞察 / 路由 / 同步为**平台无关层**；网关（消息收发）按平台适配（`BotWebSocketClient` 可替换）。
- v1 只接入 QQ；微信/钉钉/飞书作为 roadmap，不实现。

### FR10 扩展：群共享 / AA（v2，不做）
- 记录为 v2 wedge：群内@记账 + 账单归属群 + AA 分摊；本 PRD 只留接口设计空间。

## 6. 非功能需求

### NFR1 AI 脱敏与隐私（P0，答辩必问）
原则：**最小化 / 聚合化 / 匿名化 / 不落盘 / 可关闭**。
- 记账解析只送那句文本 + 分类表；月结只送聚合（无明细无备注）；异常纯本地。
- **修复泄露点**：问账不再送最近 10 笔明细（含备注）给 LLM，只送「分类 + 金额 + 日期」聚合。
- LLM 调用用匿名 user hash，不传身份；原始聊天文本过即弃；可导出 / 可删除 / 可关 AI。

### NFR2 可靠性（P0）
- 消息幂等去重（`webhook_events` 已实现）：断线重发不重复落账。
- WebSocket 心跳 + 指数退避重连（1s→30s，已实现）。
- 主动推送失败重试（最多 3 次）；服务端重启不丢计划任务。

### NFR3 平台合规（P0）
- 遵循 QQ 官方开放平台 Bot 规范：正式接入、审核、消息发送频率限制、隐私政策声明。



## 7. 成功指标

- **激活**：加好友后 24h 内完成第一笔记账的比例 ≥40%。
- **留存**：D7 记账率（连续 7 天有 ≥1 笔）≥20%（对比记账 App 行业个位数）。
- **习惯**：月活用户中"主动问账 + 收到推送"的用户占比。
- **正确率**：NLU 记账分类/金额正确率 ≥95%（规则通道）。
- **同步**：机器人落账 → App/Web 可见的端到端一致性 100%。

## 8. Week 8 编码范围

1. **账号**：QQ openid 直接开通账号（去掉 App 绑定前置）。
2. **记账闭环**：消息接收 → NLU → 落库 → 回复确认（复用 `QQMessageProcessor` + `QQIntentRouter` + `NLUService`）。
3. **主动推送**：定时任务（月末月结 / 当日异常 / 习惯提醒）→ 经 Bot 网关下发。
4. **问账修复**：`naturalQuery` 备注脱敏（§NFR1）。
5. **多端验证**：机器人记一笔，App / Web 各自同步看到。
6. **极简 Web 看账页**：登录同账号看账单 / 图表 / 关闭 AI。
