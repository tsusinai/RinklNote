## 二、服务端限流测试失败（已通过测试隔离解决）

初版验收时 8 个失败（`AuthApiTest` 5 例 + `ProfileApiTest` 3 例，断言均为 `expected:<...> but was:<429 Too Many Requests>`）：测试类内请求量触发 `InMemoryRateLimiter` 真实额度（注册 5 次/小时）所致，与业务改动无关（已用 stash 退回 HEAD 对照验证）。

**处置（审查后）**：`authRoutes` 的 `loginLimiter` / `registerLimiter` 改为可注入参数（生产默认额度不变），`AuthApiTest` / `ProfileApiTest` 注入大额度实例完成隔离。全量 333 个测试归零失败；无任何测试依赖 429 行为（已确认）。

## 三、六场景「改动后」行为（代码与单测层面）

对照基线清单的六个场景，本轮落地情况：

1. **普通数字键盘记账**：一步确认语义不变（既有用例未改断言），新增「已保存到本机 → 已同步到云端 / 失败常驻可重试」结构化反馈（`RinklSnackbarHost`）。
2. **建议记账**：建议卡带置信度、依据（服务端 `explanation` 或来源中文标签）与「📌固定 / ✕关闭 / 重新显示」入口；`needsConfirmation=true` 只回填表单不落库，`=false` 一键记入；分类/账户解析不到由静默降级为「检查后记入」。
3. **网络断开后记账**：本地落库不变；失败不再被静默吞掉，呈现「同步失败账单仍在本机 · 重试」常驻提示条；`SyncManager` 状态含待上传数与可读原因。
4. **手动同步失败**：资料页状态卡显示 待重试（原因 + 立即重试）/ 已同步（时间 + 条数）/ 需要登录；失败原因与时间持久化到 `TokenManager`，登出清除。
5. **Web 刷新失败**：`loadData` 七态结构化（partial/offline/unauthorized/conflict 等），失败资源保留旧数据不再静默置空；http.ts 把 502/503/504/断网映射为稳定中文文案；SyncCard 显示状态、上次成功时间、失败原因、受影响资源与重试。
6. **删除账单后恢复**：删除产生可撤销提示条，撤销恢复 `deleted=0、dirty=1` 并回补余额（单事务，墓碑被物理清除时按快照重插保 id/server_id）；确认框文案已从「此操作不可撤销」改为「确认后可在提示条中撤销」。**注意：记账页长按拖拽删除路径尚未接撤销通路（Task 2 范围仅 bill-edit），作为后续待办。**

## 四、人工验收进度（2026-10-01 模拟器实机冒烟）

审查后用 Android 模拟器（Medium_Phone_API_36.1，AVD）实机冒烟，以下场景**已验证通过**（截图在 `.test-shots/review-*.png`，未入库）：

1. **普通数字键盘一步确认**：选分类/账户 → 键盘输入 25 → 确认直接落库关抽屉，首页「支出 ¥25.00」与账单列表即时更新，一步确认语义未变。
2. **删除确认框新文案**：「删除这笔账单？/ 删除后会从本地和云端移除，确认后可在提示条中撤销。」
3. **删除撤销链路（审查 P1-2 修复的用户可见行为）**：确认删除 → 回列表「共 0 笔」+ 底部常驻提示条「账单已删除 · 撤销 ✕」→ 点撤销 → 账单恢复「共 1 笔」。
4. **未登录同步卡（Task 1）**：我的页显示「立即同步 · 上次同步 从未」「未登录，暂不同步 · 去登录 >」。
5. **计划页预算日额度（Task 5）**：未设预算时显示「点击设置本月预算」引导；设 ¥300 预算后计划首页出现「今日建议额度 ¥9.16」+ 计算依据「剩余可用 ¥275.00 ÷ 30 天」，与预算编辑页「日均 ¥9.16」同口径；分类预算入口约定保持。

**仍待人工验收**（需要服务端/环境）：

## 五、审查修复记录（2026-10-01 外部审查，全部闭环）

| 级别 | 问题 | 修复 |
| --- | --- | --- |
| P1 | 单条推送失败被吞后全量同步仍报「已同步」 | `sync()` 全部阶段后核对本地待上传余量，有余量如实置 `RetryPending`（含条数）并返回 `Error`；单条推送成功但仍有余量时状态同样置 `RetryPending`（本条反馈仍为 Success，针对本条） |
| P1 | 删除撤销与推送竞态：推送成功后无条件物理删除可能删掉刚恢复的账单 | `BillDao` 新增条件物理删除 `hardDeleteTombstoneById`（`WHERE id=? AND deleted=1`，单条 SQL 原子）；推送墓碑路径全部改走条件删除；拉取到服务端墓碑时跳过本地已撤销（`deleted=0`）的行，下次推送以 PUT 恢复服务端 |
| P2 | Web 401 状态基本不可见（api() 内部清 token + 硬跳转劫持） | 分类/账户/账单/关键词四个读取接口支持 `allow401` 透传，`loadData` 全部启用；`unauthorized` 状态与「去登录」入口可达；401 相关测试改为真实已登录态 |
| P2 | App 真机 / Web 认证·502·冲突人工验收未完成 | 待设备与环境（见第四节）；本轮已尽自动化验证上限 |
| P3 | 计划文档文末多余空行（`git diff --check`） | 已清除，`git diff --check main...HEAD` 通过 |

新增回归用例（SyncManagerTest）：拉取墓碑保留本地已撤销账单、全量同步部分推送失败报 RetryPending（含 pendingCount=1 断言、不清除持久化失败原因）、单条推送成功但仍有待上传时状态保持 RetryPending。
