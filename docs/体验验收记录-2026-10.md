## 二、服务端 8 个失败的原因记录（不能标记为全绿）

按计划 Task 6 要求单独记录：

- 失败集中在 `AuthApiTest`（5 例）与 `ProfileApiTest`（3 例），断言消息全部为 `expected:<...> but was:<429 Too Many Requests>`。
- **存量问题对照验证**：将本轮服务端改动 `git stash` 退回 HEAD（e880b4d）后单独重跑这两个类，**同样 5+3 个用例以相同 429 失败**，随后 `stash pop` 恢复。即与本次改动无关，是测试类内请求量触发 `InMemoryRateLimiter` 时间窗的既有问题（对本机执行速度敏感，属易 flaky 用例）。
- 失败用例清单：`email is case insensitive for register conflict and login`、`change password enforces the same rule but keeps old password working`、`register rejects password without lower case`、`malformed email is rejected with 400`、`register rejects password without upper case`、`avatar upload saves file updates me and serves via static route`、`profile put then me roundtrip carries all fields`、`profile put rejects over limit badges bad birthday and long signature`。
- 处置建议（本轮范围外）：为认证/资料类测试注入可关闭限流的测试配置，或按用例重置限流器。

## 三、六场景「改动后」行为（代码与单测层面）

对照基线清单的六个场景，本轮落地情况：

1. **普通数字键盘记账**：一步确认语义不变（既有用例未改断言），新增「已保存到本机 → 已同步到云端 / 失败常驻可重试」结构化反馈（`RinklSnackbarHost`）。
2. **建议记账**：建议卡带置信度、依据（服务端 `explanation` 或来源中文标签）与「📌固定 / ✕关闭 / 重新显示」入口；`needsConfirmation=true` 只回填表单不落库，`=false` 一键记入；分类/账户解析不到由静默降级为「检查后记入」。
3. **网络断开后记账**：本地落库不变；失败不再被静默吞掉，呈现「同步失败账单仍在本机 · 重试」常驻提示条；`SyncManager` 状态含待上传数与可读原因。
4. **手动同步失败**：资料页状态卡显示 待重试（原因 + 立即重试）/ 已同步（时间 + 条数）/ 需要登录；失败原因与时间持久化到 `TokenManager`，登出清除。
5. **Web 刷新失败**：`loadData` 七态结构化（partial/offline/unauthorized/conflict 等），失败资源保留旧数据不再静默置空；http.ts 把 502/503/504/断网映射为稳定中文文案；SyncCard 显示状态、上次成功时间、失败原因、受影响资源与重试。
6. **删除账单后恢复**：删除产生可撤销提示条，撤销恢复 `deleted=0、dirty=1` 并回补余额（单事务，墓碑被物理清除时按快照重插保 id/server_id）；确认框文案已从「此操作不可撤销」改为「确认后可在提示条中撤销」。**注意：记账页长按拖拽删除路径尚未接撤销通路（Task 2 范围仅 bill-edit），作为后续待办。**
